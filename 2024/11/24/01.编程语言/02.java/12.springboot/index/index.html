Spring Boot

Java 2024-11-24 · 更新于 2026-11-21 · 7 分钟阅读 · 1716 字

01.Spring Boot 是什么

Spring Boot 是基于 Spring Framework 的"快速开发脚手架"。它本身不是一个新框架，而是在 Spring 之上提供了一套约定优于配置的默认方案，让我们可以用极少的配置启动一个可独立运行的生产级应用。

传统 Spring 项目的痛点：

  • 大量 XML / JavaConfig 配置（DispatcherServlet、视图解析器、数据源、事务管理器……）。
  • 依赖版本需要手动对齐，Jar 冲突频繁。
  • 需要打成 war 包，部署到外部 Tomcat。

Spring Boot 的解决思路：

特性 说明
Starter 依赖 spring-boot-starter-web 等"一站式"依赖，版本由父工程统一管理
自动配置 根据 classpath 中存在的类和已有配置，自动装配需要的 Bean
内嵌容器 默认内嵌 Tomcat（可换 Jetty / Undertow），java -jar 直接运行
外部化配置 application.yml、环境变量、命令行参数统一管理，支持多环境 Profile
Actuator 健康检查、指标、端点监控，方便接入运维体系

版本说明：Spring Boot 3.x 基于 Spring Framework 6，最低要求 Java 17，并且 Java EE 包名全部从 javax.* 迁移到了 jakarta.*（如 jakarta.servlet、jakarta.persistence）。Spring Boot 2.x 已停止开源维护，新项目建议直接使用 3.x。

02.快速开始

2.1 创建项目

推荐使用官方的 Spring Initializr（start.spring.io）或 IDEA 自带的向导生成项目。Maven 项目的核心依赖如下：

<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.3.5</version>
    <relativePath/>
</parent>

<properties>
    <java.version>17</java.version>
</properties>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>

spring-boot-starter-parent 继承自 spring-boot-dependencies，里面声明了几百个常用库的兼容版本，所以引入 starter 时不需要写版本号。

2.2 启动类与接口

@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

@RestController
@RequestMapping("/hello")
class HelloController {

    @GetMapping
    public String hello(@RequestParam(defaultValue = "world") String name) {
        return "hello, " + name;
    }
}

mvn spring-boot:run              # 开发时运行
mvn clean package                # 打成可执行 fat jar
java -jar target/demo-0.0.1-SNAPSHOT.jar --server.port=9090

03.核心原理：自动配置

3.1 @SpringBootApplication

@SpringBootApplication 是一个组合注解：

  • @SpringBootConfiguration：本质是 @Configuration，标识配置类。
  • @EnableAutoConfiguration：开启自动配置。
  • @ComponentScan：默认扫描启动类所在包及其子包。

3.2 自动配置的加载流程

flowchart LR
    A["@EnableAutoConfiguration"] --> B["AutoConfigurationImportSelector"]
    B --> C["读取 META-INF/spring/
...AutoConfiguration.imports"]
    C --> D["候选自动配置类"]
    D --> E{"@Conditional 条件判断"}
    E -- 满足 --> F["注册 Bean"]
    E -- 不满足 --> G["跳过"]
  1. @EnableAutoConfiguration 通过 @Import(AutoConfigurationImportSelector.class) 导入选择器。
  2. 选择器读取所有 jar 中的 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports 文件，得到候选自动配置类列表（Spring Boot 2.7 之前是 META-INF/spring.factories，3.x 已不再从 spring.factories 读取自动配置）。
  3. 每个自动配置类上有一系列条件注解，只有满足条件才会生效。

常见条件注解：

注解 生效条件
@ConditionalOnClass classpath 中存在指定类
@ConditionalOnMissingBean 容器中没有该类型的 Bean（用户自定义优先）
@ConditionalOnProperty 配置项满足指定值
@ConditionalOnWebApplication 当前是 Web 应用

@ConditionalOnMissingBean 是"约定优于配置"的关键：用户自己定义了 Bean，自动配置就让路。

排查哪些自动配置生效，可以在启动时加 --debug，会打印 Condition Evaluation Report。

04.配置文件

4.1 application.yml

server:
  port: 8080

spring:
  application:
    name: demo
  profiles:
    active: dev
  datasource:
    url: jdbc:mysql://localhost:3306/demo
    username: root
    password: ${DB_PASSWORD}

app:
  upload:
    max-size: 10MB
    path: /data/upload

4.2 读取配置

推荐使用类型安全的 @ConfigurationProperties，而不是到处写 @Value：

@ConfigurationProperties(prefix = "app.upload")
public record UploadProperties(DataSize maxSize, String path) {}

@SpringBootApplication
@ConfigurationPropertiesScan
public class DemoApplication { ... }

4.3 多环境与优先级

  • application-dev.yml、application-prod.yml 通过 spring.profiles.active 激活。
  • 常见优先级（高 → 低）：命令行参数 > 系统环境变量 > jar 包外的 application-{profile}.yml > jar 包内的 application-{profile}.yml > jar 包外的 application.yml > jar 包内的 application.yml。
  • 环境变量会做松散绑定：SPRING_DATASOURCE_URL 对应 spring.datasource.url。

05.常用 Starter

Starter 用途
spring-boot-starter-web Spring MVC + 内嵌 Tomcat + Jackson
spring-boot-starter-webflux 响应式 Web
spring-boot-starter-data-jpa JPA / Hibernate
spring-boot-starter-jdbc JdbcTemplate + HikariCP 连接池
spring-boot-starter-data-redis Redis（默认 Lettuce 客户端）
spring-boot-starter-validation Bean Validation 参数校验
spring-boot-starter-security Spring Security
spring-boot-starter-actuator 监控端点
spring-boot-starter-test JUnit 5 + Mockito + AssertJ

MyBatis 的 starter 由 MyBatis 社区提供（mybatis-spring-boot-starter），命名规则为 xxx-spring-boot-starter；官方 starter 才是 spring-boot-starter-xxx。

06.Actuator 与生产化

management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
  endpoint:
    health:
      show-details: when-authorized
  • /actuator/health：健康检查，可作为 K8s 的存活/就绪探针。
  • /actuator/metrics：基于 Micrometer 的指标，加 micrometer-registry-prometheus 后可暴露 /actuator/prometheus。
  • 生产环境不要 include: "*"，避免暴露 env、heapdump 等敏感端点。

Spring Boot 3.x 的其他新能力：支持 GraalVM 原生镜像（AOT 编译）、基于 Micrometer Tracing 的链路追踪；3.2 起在 Java 21 上可通过 spring.threads.virtual.enabled=true 启用虚拟线程。

07.常见坑

  1. 启动类位置不对：Controller、Service 不在启动类同包或子包下，扫描不到，接口 404。
  2. javax 与 jakarta 混用：从 2.x 升级到 3.x 时，旧依赖仍引用 javax.servlet 会导致类找不到，需要升级到兼容 Jakarta EE 的版本。
  3. 自定义 Bean 覆盖失败：Spring Boot 2.1 起默认禁止 Bean 定义覆盖，同名 Bean 会启动报错。
  4. 配置不生效：检查 Profile 是否激活、配置项层级缩进、是否被更高优先级的来源覆盖。
  5. 端口被占用：Web server failed to start. Port 8080 was already in use，改 server.port 或结束占用进程。

08.面试高频问题

  • Spring Boot 自动配置原理？ @EnableAutoConfiguration → AutoConfigurationImportSelector → 读取 AutoConfiguration.imports → 条件注解过滤 → 注册 Bean。
  • Spring 和 Spring Boot 的区别？ Spring 是框架核心（IOC、AOP），Spring Boot 是基于 Spring 的快速开发方案，提供自动配置、starter、内嵌容器，不替代 Spring。
  • 如何自定义一个 starter？ 编写 xxx-autoconfigure 模块（配置类 + @ConfigurationProperties + 条件注解），在 AutoConfiguration.imports 中登记配置类，再用 xxx-starter 模块聚合依赖。
  • Spring Boot 的 jar 为什么能直接运行？ spring-boot-maven-plugin 打出的 fat jar 中，MANIFEST.MF 的 Main-Class 是 Spring Boot 的 JarLauncher，它负责加载 BOOT-INF/lib 下的依赖，再调用 Start-Class 指定的启动类。

小结

Spring Boot = Spring + 自动配置 + Starter 依赖管理 + 内嵌容器 + 外部化配置 + 生产监控。学习时抓住两条主线：一是会用（starter、yml 配置、Profile、Actuator），二是懂原理（@SpringBootApplication 组成、自动配置加载流程、条件注解）。新项目以 Spring Boot 3.x + Java 17/21 为基线。
