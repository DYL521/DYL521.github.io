Flask 基础

Python 2021-02-17 · 更新于 2026-11-21 · 19 分钟阅读 · 5540 字

01.Flask是什么

Flask 是一个用 Python 编写的轻量级 Web 框架，常被称为“微框架”（micro framework）。“微”并不是说功能弱，而是核心只保留了最基础的部分：

  • Werkzeug：WSGI 工具库，负责请求、响应、路由等底层工作。
  • Jinja2：模板引擎。
  • Click：命令行工具（flask run 等）。

数据库、表单校验、用户认证等功能都不内置，需要时通过扩展（Flask-SQLAlchemy、Flask-WTF、Flask-Login 等）按需引入。

和 Django 的对比（面试常问）：

Flask Django
定位 微框架，核心精简 全功能框架，“自带电池”
ORM 无，常配合 SQLAlchemy 自带 ORM
后台管理 无 自带 admin
项目结构 自由组织 约定好的 project/app 结构
适合场景 小型服务、API、需要高度定制 中大型业务系统、快速搭建后台

02.安装与第一个应用

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install flask

# app.py
from flask import Flask

app = Flask(__name__)


@app.route("/")
def index():
    return "Hello, Flask!"

运行开发服务器：

flask --app app run --debug
# * Running on http://127.0.0.1:5000
  • --app app 指定应用所在的模块（文件名叫 app.py 或 wsgi.py 时可以省略）。
  • --debug 开启调试模式：代码修改后自动重载，出错时显示交互式调试页面。
  • 也可以在文件末尾写 if __name__ == "__main__": app.run(debug=True)，然后 python app.py 运行。

旧教程里的 FLASK_ENV=development 已在 Flask 2.3 中移除，现在用 --debug 或 FLASK_DEBUG=1。

03.路由

3.1 基本路由与 HTTP 方法

from flask import Flask, request

app = Flask(__name__)


@app.route("/login", methods=["GET", "POST"])
def login():
    if request.method == "POST":
        return "处理登录"
    return "显示登录页"


# Flask 2.0+ 提供了快捷装饰器
@app.get("/users")
def list_users():
    return "用户列表"


@app.post("/users")
def create_user():
    return "创建用户", 201

3.2 动态路由与转换器

@app.route("/user/<username>")            # 默认 string，不含斜杠
def profile(username):
    return f"用户：{username}"


@app.route("/post/<int:post_id>")          # 只匹配整数，并自动转成 int
def show_post(post_id):
    return f"文章 ID：{post_id}，类型 {type(post_id).__name__}"


@app.route("/files/<path:subpath>")        # path 可以包含斜杠
def show_file(subpath):
    return subpath

内置转换器：string（默认）、int、float、path、uuid。

3.3 url_for 反向解析

from flask import url_for

with app.test_request_context():
    print(url_for("index"))                    # /
    print(url_for("show_post", post_id=3))     # /post/3
    print(url_for("profile", username="tom", page=2))   # /user/tom?page=2

url_for 的第一个参数是视图函数名（endpoint），不是 URL。用它生成链接，修改路由时不需要到处改代码。

04.请求对象 request

request 是一个“全局”对象，但实际上每个请求都是独立的（见第 8 节上下文）。

from flask import request


@app.post("/demo")
def demo():
    page = request.args.get("page", 1, type=int)   # 查询参数 ?page=2
    name = request.form.get("name")                 # 表单数据
    data = request.get_json(silent=True)            # JSON 请求体，解析失败返回 None
    token = request.headers.get("Authorization")    # 请求头
    sid = request.cookies.get("sid")                # Cookie
    f = request.files.get("avatar")                 # 上传的文件
    return {
        "method": request.method,
        "path": request.path,
        "page": page,
        "name": name,
        "json": data,
    }

request.args、request.form 都是 MultiDict，用 .get() 取值不会因为缺少键而报错；直接用 request.form["name"] 取不存在的键会返回 400 错误。

05.响应

视图函数的返回值会被转换成响应对象：

from flask import jsonify, make_response, redirect, abort, url_for


@app.get("/a")
def a():
    return "纯文本"                          # 字符串 -> text/html


@app.get("/b")
def b():
    return {"code": 0, "msg": "ok"}          # dict 自动转 JSON（list 也可以，Flask 2.2+）


@app.get("/c")
def c():
    return jsonify(code=0, data=[1, 2, 3])   # 显式返回 JSON


@app.get("/d")
def d():
    return "已创建", 201, {"X-Custom": "1"}   # (body, 状态码, 响应头)


@app.get("/e")
def e():
    resp = make_response("设置 cookie")
    resp.set_cookie("sid", "abc123", httponly=True)
    return resp


@app.get("/old")
def old():
    return redirect(url_for("index"))        # 302 重定向


@app.get("/admin")
def admin():
    abort(403)                               # 直接中断，返回 403

自定义错误页：

@app.errorhandler(404)
def not_found(e):
    return {"code": 404, "msg": "资源不存在"}, 404

06.模板

Flask 默认从项目下的 templates/ 目录加载 Jinja2 模板，static/ 目录存放静态文件。

project/
├── app.py
├── templates/
│   └── hello.html
└── static/
    └── style.css

from flask import render_template


@app.get("/hello/<name>")
def hello(name):
    return render_template("hello.html", name=name, items=["a", "b"])

<!-- templates/hello.html -->
<link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}">
<h1>你好，{{ name }}</h1>
<ul>
  {% for item in items %}
    <li>{{ item }}</li>
  {% endfor %}
</ul>

渲染 .html 等模板时，Jinja2 默认会对双花括号表达式输出的内容做 HTML 转义，防止 XSS。

07.配置与 session

import os
from flask import Flask, session

app = Flask(__name__)
app.config["SECRET_KEY"] = os.environ.get("SECRET_KEY", "dev-only-key")
# 也可以 app.config.from_object("config.ProdConfig") 或 app.config.from_prefixed_env()


@app.post("/login")
def login():
    session["user_id"] = 1
    return "登录成功"


@app.get("/me")
def me():
    return {"user_id": session.get("user_id")}

Flask 默认的 session 是基于 Cookie 的客户端 session：数据经过签名后存放在浏览器 Cookie 中，用户能看到内容（只是 Base64 编码），但无法篡改。因此：

  • 必须设置 SECRET_KEY，且不能泄露；
  • 不要在 session 里存敏感信息或大量数据。需要服务端 session 可以使用 Flask-Session 等扩展。

08.上下文：current_app、g、request

Flask 有两种上下文：

  • 应用上下文：current_app（当前应用）、g（一次请求/上下文内的临时存储）。
  • 请求上下文：request、session。

每个请求进来时，Flask 会推入这两个上下文，所以在视图函数里可以直接使用这些“全局”对象，而且它们在多线程下互不干扰（底层基于 contextvars 实现）。

from flask import g


@app.before_request
def load_user():
    g.user = {"id": 1, "name": "tom"}     # 每个请求开始时执行


@app.after_request
def add_header(response):
    response.headers["X-App"] = "demo"     # 每个请求返回前执行
    return response


@app.get("/whoami")
def whoami():
    return g.user

在请求之外（比如脚本、单元测试）使用 current_app 会报 RuntimeError: Working outside of application context，需要手动推入上下文：

with app.app_context():
    print(current_app.name)

09.蓝图 Blueprint

项目变大后，用蓝图按功能拆分路由：

# user/views.py
from flask import Blueprint

user_bp = Blueprint("user", __name__, url_prefix="/user")


@user_bp.get("/<int:uid>")
def detail(uid):
    return {"uid": uid}

# app.py
from flask import Flask
from user.views import user_bp


def create_app():
    app = Flask(__name__)
    app.register_blueprint(user_bp)
    return app

蓝图中的视图 endpoint 会带上蓝图名前缀，反向解析时写 url_for("user.detail", uid=1)。create_app() 这种应用工厂模式便于为测试、开发、生产创建不同配置的应用实例，也是 Flask 官方推荐的写法（flask --app "app:create_app" run）。

10.常见坑

  1. 开发服务器不能用于生产：flask run / app.run() 仅用于开发，生产环境使用 Gunicorn、uWSGI、Waitress 等 WSGI 服务器，例如 gunicorn -w 4 "app:create_app()"。
  2. 生产环境不要开 debug：调试页面可以执行任意 Python 代码，暴露在公网非常危险。
  3. 路由末尾斜杠：@app.route("/about/") 访问 /about 会被重定向到 /about/；而 @app.route("/about") 访问 /about/ 会返回 404。
  4. 循环导入：app.py 导入视图、视图又导入 app，容易循环导入。使用蓝图 + 应用工厂，在视图中通过 current_app 访问应用。
  5. g 不能跨请求保存数据：每个请求结束后 g 就失效了，跨请求的数据放 session、数据库或缓存。

11.小结

  • Flask 核心精简：路由（Werkzeug）+ 模板（Jinja2），其余靠扩展。
  • 重点 API：@app.route / @app.get、request、render_template、url_for、redirect、abort、session、g。
  • 视图可以直接返回字符串、字典、元组或 Response 对象。
  • 项目变大后使用蓝图 + 应用工厂组织代码；生产部署用 WSGI 服务器，不开 debug。
