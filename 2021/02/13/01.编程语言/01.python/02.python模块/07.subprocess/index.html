subprocess

Python 2021-02-13 · 17 分钟阅读 · 5085 字

01.subprocess是什么

subprocess 是 Python 标准库中用来创建子进程、执行外部命令的模块：可以运行 shell 命令，拿到它的输出、错误信息和退出码，还可以通过管道与子进程交互。

它是 os.system、os.popen 等老接口的官方替代品：

方式 能拿输出 能拿退出码 推荐程度
os.system(cmd) 不能（直接打印到终端） 能 不推荐
os.popen(cmd) 能 不方便 不推荐
subprocess.run() 能 能 首选
subprocess.Popen 能 能 需要细粒度控制时用

02.subprocess.run：最常用的接口

run() 会执行命令、等待它结束，然后返回一个 CompletedProcess 对象。

import subprocess

result = subprocess.run(["ls", "-l", "/tmp"], capture_output=True, text=True)

print(result.args)         # ['ls', '-l', '/tmp']
print(result.returncode)   # 退出码，0 表示成功
print(result.stdout)       # 标准输出（因为 text=True，所以是 str）
print(result.stderr)       # 标准错误

常用参数：

参数 作用
args 要执行的命令，推荐传列表：["git", "status"]
capture_output=True 捕获 stdout 和 stderr，等价于 stdout=PIPE, stderr=PIPE
text=True 以字符串而不是 bytes 返回输出（老写法 universal_newlines=True）
encoding="utf-8" 指定编码，同时也会开启文本模式
check=True 退出码非 0 时抛出 CalledProcessError
timeout=10 超时秒数，超时会杀掉子进程并抛 TimeoutExpired
cwd="/path" 子进程的工作目录
env={...} 子进程的环境变量（会整体替换，而不是追加）
input="..." 写入子进程标准输入的数据
shell=True 通过 shell 执行（见下文的安全问题）

03.错误处理

import subprocess

try:
    result = subprocess.run(
        ["git", "rev-parse", "HEAD"],
        capture_output=True,
        text=True,
        check=True,       # 非 0 退出码直接抛异常
        timeout=5,
    )
    print("当前提交:", result.stdout.strip())
except subprocess.CalledProcessError as e:
    print("命令失败，退出码:", e.returncode)
    print("错误输出:", e.stderr)
except subprocess.TimeoutExpired:
    print("命令超时")
except FileNotFoundError:
    print("找不到 git 可执行文件")

注意三种异常的区别：

  • FileNotFoundError：命令本身不存在（列表形式、不经过 shell 时）。
  • CalledProcessError：命令执行了，但退出码不是 0（需要 check=True）。
  • TimeoutExpired：超过了 timeout。

只想要输出的话，还有一个快捷函数 check_output，相当于 run(..., check=True, stdout=PIPE).stdout：

out = subprocess.check_output(["python", "--version"], text=True)
print(out)   # Python 3.12.3

04.输入、重定向与环境变量

import os
import subprocess

# 1. 给子进程传入标准输入
r = subprocess.run(["grep", "py"], input="a.py\nb.txt\nc.py\n",
                   capture_output=True, text=True)
print(r.stdout)        # a.py\nc.py\n

# 2. 把 stderr 合并到 stdout
r = subprocess.run(["ls", "/not-exist", "/tmp"],
                   stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True)

# 3. 丢弃输出
subprocess.run(["ping", "-c", "1", "127.0.0.1"], stdout=subprocess.DEVNULL)

# 4. 输出直接写到文件
with open("out.log", "w") as f:
    subprocess.run(["ls", "-l"], stdout=f)

# 5. 在原有环境变量基础上追加，而不是整体替换
env = {**os.environ, "APP_ENV": "test"}
subprocess.run(["python", "app.py"], env=env)

05.shell=True 与命令注入

import subprocess

# 推荐：列表形式，不经过 shell，参数原样传给程序
subprocess.run(["ls", "-l", "my dir"])

# shell=True：传字符串，由 /bin/sh 解析，可以用管道、通配符、重定向
subprocess.run("ls -l | grep py > result.txt", shell=True)

shell=True 的风险在于命令注入：

filename = "a.txt; rm -rf ~"          # 来自用户输入
subprocess.run(f"cat {filename}", shell=True)   # 危险！分号后面的命令也会执行
subprocess.run(["cat", filename])                # 安全：整个字符串只是一个参数

原则：

  • 能用列表就用列表，绝不把用户输入拼进 shell=True 的字符串。
  • 确实需要 shell 时，用 shlex.quote() 对参数转义。
  • 想把一条命令字符串拆成列表，可以用 shlex.split("ls -l 'my dir'") → ['ls', '-l', 'my dir']。

06.Popen：更底层的控制

run() 内部就是基于 Popen 实现的。需要不等待子进程结束、实时读取输出或者搭建管道时，直接使用 Popen。

import subprocess

# 实时逐行读取输出（例如长时间运行的构建任务）
with subprocess.Popen(
    ["ping", "-c", "3", "127.0.0.1"],
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
    text=True,
) as proc:
    for line in proc.stdout:
        print("输出:", line, end="")

print("退出码:", proc.returncode)

用管道连接两个进程，相当于 ps aux | grep python：

import subprocess

p1 = subprocess.Popen(["ps", "aux"], stdout=subprocess.PIPE)
p2 = subprocess.Popen(["grep", "python"], stdin=p1.stdout,
                      stdout=subprocess.PIPE, text=True)
p1.stdout.close()          # 让 p1 能在 p2 提前退出时收到 SIGPIPE
out, _ = p2.communicate()
print(out)

Popen 常用方法：

方法 说明
poll() 检查是否结束，未结束返回 None，否则返回退出码
wait(timeout=None) 等待结束并返回退出码
communicate(input=None, timeout=None) 写入 stdin、读完 stdout/stderr 并等待结束，返回 (out, err)
terminate() / kill() 发送 SIGTERM / SIGKILL
pid 子进程的进程号

07.常见坑

  1. 管道死锁：使用 stdout=PIPE 时如果调用 wait()，而子进程输出很多、把管道缓冲区写满了，子进程会阻塞在写操作上，父进程又在等它结束，于是死锁。应该使用 communicate() 或 run()。
  2. communicate 超时后要手动杀进程：Popen.communicate(timeout=...) 超时抛异常时子进程不会被自动杀死，需要 proc.kill() 后再 proc.communicate() 回收。run(timeout=...) 会帮你做这件事。
  3. 字符串命令不加 shell=True：subprocess.run("ls -l") 在 Linux 上会把整个 "ls -l" 当成程序名去找，报 FileNotFoundError。
  4. 忘记 text=True：得到的是 bytes，result.stdout.strip() == "ok" 永远为 False。
  5. env 会整体替换环境变量：只传 {"A": "1"} 会导致子进程连 PATH 都没有，应使用 {**os.environ, "A": "1"}。
  6. cd 不会生效：subprocess.run("cd /tmp", shell=True) 只改变了子 shell 的目录，对当前 Python 进程没影响，应该用 cwd 参数或 os.chdir()。
  7. 编码问题：Windows 下命令输出可能不是 UTF-8，解码出错时可以显式指定 encoding 和 errors="replace"。

08.小结

  • 首选 subprocess.run(列表, capture_output=True, text=True, check=True, timeout=...)，基本覆盖九成场景。
  • 需要实时输出、管道组合或异步控制时用 Popen，读写管道时用 communicate() 避免死锁。
  • 尽量不用 shell=True，绝不把不可信输入拼进 shell 命令。
  • 面试可能问：os.system 与 subprocess 的区别、shell=True 的风险、PIPE 死锁的原因。
