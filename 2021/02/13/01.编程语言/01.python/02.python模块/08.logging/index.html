01.为什么用logging

调试时用 print 很方便，但到了正式项目就会遇到问题：不能按级别过滤、不能同时输出到控制台和文件、没有时间和位置信息、上线后关不掉。标准库 logging 解决的就是这些问题：

  • 按级别过滤日志，开发时看 DEBUG，线上只看 WARNING 以上。
  • 同一条日志可以同时发往多个目的地（控制台、文件、网络等）。
  • 统一的格式：时间、模块名、行号、进程/线程等。
  • 第三方库也使用 logging，可以统一管理所有日志。

02.日志级别

级别 数值 使用场景
DEBUG 10 详细的调试信息
INFO 20 程序正常运行的关键节点
WARNING 30 出现意外但程序还能继续（默认级别）
ERROR 40 某个功能出错
CRITICAL 50 严重错误，程序可能无法继续运行

只有大于等于设定级别的日志才会被输出。

03.快速上手：basicConfig

import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s [%(levelname)s] %(name)s:%(lineno)d - %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",
)

logging.debug("调试信息")
logging.info("服务启动，端口 %s", 8000)
logging.warning("磁盘空间不足")
logging.error("连接数据库失败")
logging.critical("系统崩溃")

输出示例：

2024-01-01 12:00:00 [INFO] root:9 - 服务启动，端口 8000

basicConfig 的常用参数：level、format、datefmt、filename（写入文件）、filemode、handlers、encoding（3.9+）、force（3.8+，强制重新配置）。

常用的格式字段：

字段 含义
%(asctime)s 时间
%(levelname)s 级别名
%(name)s logger 名称
%(message)s 日志内容
%(filename)s / %(lineno)d / %(funcName)s 文件名 / 行号 / 函数名
%(process)d / %(thread)d 进程 ID / 线程 ID

04.四大组件

logging 的核心由四个组件组成，面试经常问：

  • Logger：日志记录器，代码里直接调用的对象（logger.info(...)）。
  • Handler：处理器，决定日志发到哪里，如 StreamHandler（控制台）、FileHandler（文件）。
  • Formatter：格式化器，决定日志长什么样。
  • Filter：过滤器，对日志做更细粒度的筛选。

一条日志的流程：Logger 检查级别 → 经过 Logger 的 Filter → 交给它的每个 Handler → Handler 再检查自己的级别和 Filter → 用 Formatter 格式化后输出 → 如果 propagate=True，继续交给父 logger 的 Handler。

import logging

logger = logging.getLogger("myapp")
logger.setLevel(logging.DEBUG)          # logger 本身放行 DEBUG 及以上

fmt = logging.Formatter("%(asctime)s [%(levelname)s] %(name)s - %(message)s")

console = logging.StreamHandler()
console.setLevel(logging.INFO)          # 控制台只看 INFO 及以上
console.setFormatter(fmt)

file_handler = logging.FileHandler("app.log", encoding="utf-8")
file_handler.setLevel(logging.DEBUG)    # 文件记录全部
file_handler.setFormatter(fmt)

logger.addHandler(console)
logger.addHandler(file_handler)

logger.debug("只会写进文件")
logger.info("控制台和文件都有")

05.logger 的层级与 getLogger(name)

logger 是按名字组织成树形结构的，用 . 分隔：myapp.db 是 myapp 的子 logger，所有 logger 的根是 root logger。

  • logging.getLogger(name)：同名返回同一个对象（单例）。
  • logging.getLogger()：不传名字返回 root logger。
  • logging.info(...) 这种模块级函数用的就是 root logger。

推荐在每个模块里这样写：

# myapp/db.py
import logging

logger = logging.getLogger(__name__)   # 名字就是 "myapp.db"

def query():
    logger.info("执行查询")

模块里只负责“产生日志”，不添加 Handler；在程序入口统一配置 root 或 myapp logger，子 logger 的日志会通过 propagate 传递上去。写库的时候更是如此：不要在库里调用 basicConfig，最多给库的顶层 logger 加一个 logging.NullHandler()。

06.记录异常

import logging

logger = logging.getLogger(__name__)

try:
    1 / 0
except ZeroDivisionError:
    logger.exception("计算失败")             # ERROR 级别，并自动附带堆栈
    # 等价于 logger.error("计算失败", exc_info=True)

logger.exception() 只应该在 except 块中调用。

07.日志切割

日志文件会越来越大，logging.handlers 里提供了按大小和按时间切割的 Handler：

import logging
from logging.handlers import RotatingFileHandler, TimedRotatingFileHandler

# 按大小：单个文件最大 10MB，保留 5 个备份 app.log.1 ~ app.log.5
size_handler = RotatingFileHandler(
    "app.log", maxBytes=10 * 1024 * 1024, backupCount=5, encoding="utf-8"
)

# 按时间：每天午夜切一次，保留 7 天
time_handler = TimedRotatingFileHandler(
    "app_daily.log", when="midnight", backupCount=7, encoding="utf-8"
)

08.使用 dictConfig 集中配置

项目中通常用字典（或从 YAML/JSON 读取）统一配置，Django 的 LOGGING 设置就是这种格式：

import logging
import logging.config

LOGGING = {
    "version": 1,
    "disable_existing_loggers": False,
    "formatters": {
        "standard": {
            "format": "%(asctime)s [%(levelname)s] %(name)s:%(lineno)d - %(message)s",
        },
    },
    "handlers": {
        "console": {
            "class": "logging.StreamHandler",
            "level": "INFO",
            "formatter": "standard",
        },
        "file": {
            "class": "logging.handlers.RotatingFileHandler",
            "level": "DEBUG",
            "formatter": "standard",
            "filename": "app.log",
            "maxBytes": 10485760,
            "backupCount": 5,
            "encoding": "utf-8",
        },
    },
    "loggers": {
        "myapp": {"handlers": ["console", "file"], "level": "DEBUG", "propagate": False},
    },
    "root": {"handlers": ["console"], "level": "WARNING"},
}

logging.config.dictConfig(LOGGING)
logging.getLogger("myapp.service").info("配置完成")

disable_existing_loggers 默认是 True，会把配置之前已经创建的 logger 禁用掉，一般建议显式设为 False。

09.常见坑

  1. basicConfig 只生效一次：如果 root logger 已经有 Handler（比如之前调用过 logging.info() 或某个库先配置了），再调用 basicConfig 不会有任何效果。可以传 force=True 强制重新配置。
  2. 日志重复输出：
    • 在函数里反复 addHandler，每调用一次就多一个 Handler；
    • 子 logger 和 root 都挂了 Handler，日志通过 propagate 被打印两次。解决办法是只在一处配置 Handler，或设置 logger.propagate = False。
  3. 级别要同时满足 Logger 和 Handler：Logger 设为 WARNING 时，Handler 设成 DEBUG 也看不到 INFO 日志。
  4. 使用惰性格式化：推荐 logger.info("用户 %s 登录", user) 而不是 logger.info(f"用户 {user} 登录")。前者只在日志真正需要输出时才拼接字符串，级别被过滤时没有额外开销。
  5. 多进程写同一个文件：logging 是线程安全的，但不保证多进程安全，多个进程同时写同一个 RotatingFileHandler 切割时可能出错丢日志。可以让每个进程写不同的文件，或者用 QueueHandler + QueueListener 汇总到一个进程中写入，或直接输出到 stdout 交给容器/日志系统收集。

10.小结

  • 四大组件：Logger 产生日志、Handler 决定去向、Formatter 决定格式、Filter 做筛选。
  • 模块中用 logging.getLogger(__name__)，在程序入口统一配置（basicConfig 或 dictConfig）。
  • 记录异常用 logger.exception()，日志参数用 %s 惰性格式化。
  • 注意 basicConfig 只生效一次、Handler 重复添加和 propagate 导致的重复输出。
