Keepalived 基础

操作系统 2021-02-09 · 更新于 2026-11-21 · 6 分钟阅读 · 1664 字

01.Keepalived 是什么

Keepalived 是一个基于 VRRP 协议实现的高可用软件，最初是为 LVS 设计的，现在常用于给 Nginx、HAProxy、MySQL 等服务做主备切换。

它主要提供两大功能：

  1. 高可用（VRRP）：多台服务器共享一个虚拟 IP（VIP），主节点故障时 VIP 自动漂移到备节点，客户端无感知。
  2. 负载均衡与健康检查（LVS）：管理 IPVS 规则，对后端真实服务器做健康检查，自动剔除故障节点。

日常最常见的用法是第一种：Keepalived + Nginx 实现负载均衡层的高可用，解决单台 Nginx 的单点故障问题。

02.VRRP 协议原理

VRRP（Virtual Router Redundancy Protocol，虚拟路由冗余协议）最初用于解决网关单点问题：把多台路由器组成一个虚拟路由器，对外只暴露一个虚拟 IP。

核心概念：

概念 说明
虚拟路由器 由同一个 virtual_router_id（VRID，1~255）标识的一组节点
VIP 虚拟 IP，客户端实际访问的地址
MASTER 当前持有 VIP、对外提供服务的节点
BACKUP 备用节点，监听 MASTER 的通告
优先级 priority 1~254，数值大的成为 MASTER
通告 Advertisement MASTER 定期（默认 1 秒）组播发送 VRRP 报文，宣告自己存活

工作过程：

sequenceDiagram
    participant M as MASTER (priority 100)
    participant B as BACKUP (priority 90)
    participant C as 客户端
    M->>B: 每秒组播 VRRP 通告 (224.0.0.18)
    C->>M: 访问 VIP 192.168.1.100
    Note over M: 宕机 / Nginx 挂掉
    B->>B: 约 3 个通告周期未收到通告
    B->>B: 切换为 MASTER，绑定 VIP
    B-->>C: 发送免费 ARP，更新 VIP 对应的 MAC
    C->>B: 继续访问 VIP
  • VRRP 报文使用 IP 协议号 112，默认组播地址 224.0.0.18。
  • BACKUP 在大约 3 个通告间隔 + 一个与优先级相关的偏移时间内收不到通告，就认为 MASTER 失效。
  • 新 MASTER 会发送免费 ARP（Gratuitous ARP），让交换机和同网段主机更新 VIP 对应的 MAC 地址。

03.安装与目录

# RHEL/CentOS/Rocky
yum install -y keepalived
# Debian/Ubuntu
apt install -y keepalived

keepalived --version             # 查看版本，主流为 2.x
systemctl enable --now keepalived
journalctl -u keepalived -f      # 查看日志
  • 主配置文件：/etc/keepalived/keepalived.conf
  • 检测配置语法（2.x 支持）：keepalived -t -f /etc/keepalived/keepalived.conf

04.配置文件结构

keepalived.conf 主要由三部分组成：

配置块 作用
global_defs 全局配置，如 router_id、通知邮件、脚本安全选项
vrrp_script / vrrp_instance VRRP 实例：VIP、优先级、健康检查脚本
virtual_server LVS 虚拟服务与后端真实服务器（使用 LVS 时才需要）

05.实战：Keepalived + Nginx 主备高可用

环境规划：

角色 IP 说明
nginx-01 192.168.1.11 MASTER
nginx-02 192.168.1.12 BACKUP
VIP 192.168.1.100 对外提供服务的地址

两台机器都安装好 Nginx 和 Keepalived，Nginx 配置保持一致。

5.1 Nginx 健康检查脚本

/etc/keepalived/check_nginx.sh：

#!/bin/bash
# Nginx 进程不存在则返回非 0，Keepalived 据此降低优先级
if ! pidof nginx > /dev/null; then
    exit 1
fi
# 也可以检查端口是否能正常响应
curl -s -o /dev/null --max-time 2 http://127.0.0.1/ || exit 1
exit 0

chmod +x /etc/keepalived/check_nginx.sh

5.2 MASTER 配置（192.168.1.11）

global_defs {
    router_id nginx_01
    script_user root
    enable_script_security
}

vrrp_script check_nginx {
    script "/etc/keepalived/check_nginx.sh"
    interval 2          # 每 2 秒执行一次
    timeout 3           # 脚本超时时间
    weight -30          # 失败时优先级减 30
    fall 2              # 连续失败 2 次判定为失败
    rise 2              # 连续成功 2 次判定为恢复
}

vrrp_instance VI_1 {
    state MASTER
    interface eth0              # 绑定 VIP 的网卡，按实际网卡名修改
    virtual_router_id 51        # 主备必须一致，同网段不同集群必须不同
    priority 100
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass 1qaz2wsx      # 最多 8 位，主备一致
    }
    virtual_ipaddress {
        192.168.1.100/24
    }
    track_script {
        check_nginx
    }
}

5.3 BACKUP 配置（192.168.1.12）

与 MASTER 基本相同，只需修改以下几项：

global_defs {
    router_id nginx_02
}

vrrp_instance VI_1 {
    state BACKUP
    priority 90
    # 其余与 MASTER 保持一致
}

5.4 优先级计算

  • MASTER 正常：100；BACKUP：90，MASTER 持有 VIP。
  • MASTER 上 Nginx 挂掉：脚本失败，100 - 30 = 70 < 90，VIP 漂移到 BACKUP。
  • MASTER 上 Nginx 恢复：优先级回到 100，默认会抢占回 VIP。

所以 weight 的绝对值必须大于主备优先级之差，否则检测失败也不会切换。

5.5 验证

systemctl restart keepalived       # 两台都启动
ip addr show eth0                  # MASTER 上能看到 192.168.1.100
systemctl stop nginx               # 在 MASTER 上停掉 Nginx
ip addr show eth0                  # VIP 从 MASTER 消失，出现在 BACKUP 上
curl http://192.168.1.100          # 访问依然正常

注意：用 ifconfig 看不到 Keepalived 添加的 VIP（它是网卡的第二个地址），要用 ip addr 查看。

06.抢占与非抢占

  • 抢占模式（默认）：高优先级节点恢复后立即抢回 VIP，会发生两次切换。
  • 非抢占模式：两台都配置 state BACKUP，并在高优先级节点加上 nopreempt，恢复后不抢 VIP，减少抖动。
vrrp_instance VI_1 {
    state BACKUP
    nopreempt
    priority 100
    ...
}

07.常见问题

  1. 脑裂（Split Brain）：两台都认为自己是 MASTER，同时持有 VIP。常见原因是防火墙拦截了 VRRP 报文、网络分区、virtual_router_id 与同网段其他集群冲突。放行 VRRP：

    firewall-cmd --permanent --add-rich-rule='rule protocol value="vrrp" accept'
firewall-cmd --reload

  2. 云服务器不支持组播：大多数公有云 VPC 不支持组播和免费 ARP，需要使用单播（unicast_src_ip + unicast_peer），且 VIP 往往要使用云厂商提供的"高可用虚拟 IP（HAVIP）"产品配合。

    unicast_src_ip 192.168.1.11
unicast_peer {
    192.168.1.12
}

  3. 脚本不执行：开启 enable_script_security 后，脚本及其所在目录不能被非 root 用户写入，否则会被拒绝执行，日志中可以看到相关提示。

  4. 只检测 Keepalived 自己：如果不配置 track_script，只有整台机器宕机或 Keepalived 停止才会切换，Nginx 挂了 VIP 也不会漂移。

  5. Nginx 监听 VIP 失败：BACKUP 上 Nginx 如果 listen 192.168.1.100:80，启动时 VIP 不在本机会报错，可监听 0.0.0.0 或设置内核参数 net.ipv4.ip_nonlocal_bind = 1。

08.面试要点

  • Keepalived 基于 VRRP，通过 VIP 漂移实现高可用；MASTER 定期发送通告，BACKUP 超时未收到即接管。
  • 健康检查通过 vrrp_script + track_script，用 weight 调整优先级或直接让实例进入 FAULT 状态。
  • 脑裂的原因与预防：放行 VRRP、双心跳线、仲裁（如检测网关可达性）、监控同时持有 VIP 的情况。

小结

Keepalived 的核心就是 VRRP + VIP + 优先级 + 健康检查脚本。与 Nginx 配合时，关键配置点是：主备 virtual_router_id 和认证一致、优先级差小于 weight 绝对值、正确配置 track_script、防火墙放行 VRRP；在公有云环境中则改用单播并配合云厂商的高可用 VIP。
