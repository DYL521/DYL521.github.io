01.常用命令总览

Git 命令很多，但日常开发主要围绕四件事：保存修改、组织分支、同步远程、撤销误操作。下面这张图可以先作为索引，具体用法见后面的文字速查。

mindmap
  root((Git 常用命令))
    保存修改
      git status
      git add
      git diff
      git commit
    组织分支
      git branch
      git switch
      git merge
    同步远程
      git fetch
      git pull
      git push
    撤销与找回
      git restore
      git revert
      git reset
      git reflog

02.先理解三个区域

区域 含义 相关命令
工作区 当前实际看到和编辑的文件 git diff、git restore
暂存区（Index） 下一次准备提交的内容 git add、git restore --staged
本地仓库 已形成的提交历史 git commit、git log
远程仓库 与团队共享的仓库副本 git fetch、git pull、git push

基本流向是：

工作区 --git add--> 暂存区 --git commit--> 本地仓库 --git push--> 远程仓库

git diff 默认比较工作区和暂存区，git diff --staged 比较暂存区和最新提交。提交前同时检查这两个差异，可以避免漏提交或多提交。

03.一套完整的日常开发流程

# 1. 从最新的主干创建功能分支
git switch main
git pull --ff-only
git switch -c feature/login

# 2. 修改代码后检查状态与差异
git status
git diff
git add -p                   # 按代码块选择要提交的内容
git diff --staged            # 检查真正将进入提交的内容

# 3. 提交并首次推送到远程同名分支
git commit -m "新增用户登录接口"
git push -u origin feature/login

pull --ff-only 只允许快进更新；如果本地与远程历史已经分叉，它会停止而不是自动产生一个合并提交。此时先检查 git log --oneline --graph --decorate --all，再明确选择 merge 或 rebase，不要盲目强制推送。

04.文字速查表

4.1 初始化、查看与提交

命令 作用
git init 在当前目录初始化仓库
git clone <url> 克隆远程仓库
git status 查看文件状态和当前分支
git add <file> 把指定文件的变化放入暂存区
git add -p 按代码块交互式暂存，适合拆分提交
git commit -m "说明" 用暂存区内容创建提交
git log --oneline --graph --decorate 以紧凑图形查看提交历史
git show <commit> 查看某次提交的内容

不要习惯性对所有修改直接执行 git add .。先用 git status 确认范围，尤其要排除密钥、本地配置和生成文件。

4.2 分支与合并

命令 作用
git branch 查看本地分支
git switch <branch> 切换到已有分支
git switch -c <branch> 创建并切换到新分支
git merge <branch> 把指定分支合并到当前分支
git branch -d <branch> 删除已经合并的本地分支

switch 负责切换分支，restore 负责恢复文件。相比老命令 checkout，这两个命令的职责更清楚。

4.3 远程同步

命令 作用
git fetch origin 获取远程更新，不修改当前工作分支
git pull --ff-only 获取并快进更新当前分支
git push 推送当前分支已经设置的 upstream
git push -u origin <branch> 推送并建立本地分支与远程分支的跟踪关系

fetch 只更新远程跟踪引用，适合先查看别人做了什么；pull 可以粗略理解为 fetch 加一次整合操作，并不等于无条件覆盖本地文件。

05.撤销修改：先看修改到了哪一步

场景 推荐命令 是否保留工作区修改
文件还没暂存，想丢弃修改 git restore <file> 否，谨慎执行
已暂存，但不想提交 git restore --staged <file> 是，只退出暂存区
想修改最近一次本地提交 git commit --amend 会重写最近一次提交
想撤销已共享提交的 影响 git revert <commit> 新增一个反向提交，历史可共享
本地提交想退回一步 git reset --soft HEAD^ 保留在暂存区
本地提交想退回一步并重新组织 git reset HEAD^ 保留在工作区，退出暂存区

这里“撤销已共享提交的 影响”指撤销它带来的代码变化。revert 不删除原提交，而是创建内容相反的提交，适合团队分支；reset 会移动分支指针，可能改写已经推送的历史。

如果误执行了本地 reset，可以尽快用 git reflog 查找分支之前指向的提交，再创建分支找回：

git reflog
git switch -c recover-work <commit>

reflog 有保存期限且通常只存在本地，不能替代备份和远程推送。

06.需要谨慎的命令

  • git restore <file>：未提交修改被丢弃后通常无法从 Git 找回。
  • git reset --hard：同时移动分支并丢弃工作区、暂存区修改，执行前确认 git status。
  • git clean -fd：会删除未跟踪文件，先用 git clean -nd 预览，并注意是否还需要 -x 及其风险。
  • 强制推送：共享分支不要直接 --force；确需重写自己的远程分支时使用 git push --force-with-lease，避免覆盖刚发现的他人提交。

更系统的概念和原理可继续阅读本目录的《Git》学习笔记。
