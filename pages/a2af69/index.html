01.什么是时间复杂度

时间复杂度描述的是：当输入规模增大时，算法所需基本操作次数如何增长。它不是程序在某台机器上运行的具体秒数，而是用于比较算法增长趋势的抽象指标。

大 O 记号 O(f(n))O(f(n))O(f(n)) 表示增长的上界量级。分析时通常：

  • 保留增长最快的项，例如 n2+n+10n^2+n+10n​2​​+n+10 写成 O(n2)O(n^2)O(n​2​​)。
  • 忽略常数系数，例如 3n3n3n 写成 O(n)O(n)O(n)。
  • 先明确输入规模 nnn 是什么：数组长度、树节点数，还是数值本身的位数。
  • 有多个输入时不要随意合并，例如长度分别为 mmm、nnn 的两个数组应写成 O(m+n)O(m+n)O(m+n) 或 O(mn)O(mn)O(mn)。

02.常见复杂度对照

复杂度 名称 典型例子
O(1)O(1)O(1) 常数 数组按下标访问、哈希表平均查找
O(logn)O(\log n)O(logn) 对数 有序数组二分查找
O(n)O(n)O(n) 线性 遍历数组、单链表查找
O(nlogn)O(n\log n)O(nlogn) 线性对数 归并排序、堆排序、快速排序平均情况
O(n2)O(n^2)O(n​2​​) 平方 枚举数组中所有无序数对
O(2n)O(2^n)O(2​n​​) 指数 枚举含 nnn 个元素集合的所有子集
O(n!)O(n!)O(n!) 阶乘 枚举 nnn 个不同元素的所有排列

复杂度关注的是增长趋势，不表示 O(n)O(n)O(n) 在所有输入规模下都比 O(logn)O(\log n)O(logn) 慢，也不能代替常数开销、缓存命中和实际基准测试。

03.循环代码怎么计算

3.1 顺序执行与嵌套执行

顺序执行的代码通常取较大项；完整嵌套的循环通常把执行次数相乘：

for x in a:              # O(m)
    print(x)

for y in b:              # O(n)，与上一段合计 O(m+n)
    print(y)

for x in a:              # 外层 m 次
    for y in b:          # 每次内层 n 次，合计 O(mn)
        print(x, y)

只有两个输入规模相同且都为 nnn 时，O(mn)O(mn)O(mn) 才写成 O(n2)O(n^2)O(n​2​​)。

3.2 两层循环不一定是 O(n²)

“两层 for 循环都是 O(n2)O(n^2)O(n​2​​)”是错误概括，必须看每层的实际迭代次数：

for i in range(n):
    for j in range(10):      # 内层固定 10 次
        pass                 # 总计 10n，仍是 O(n)

for i in range(n):
    for j in range(i, n):    # n + (n-1) + ... + 1
        pass                 # n(n+1)/2，所以是 O(n²)

类似地，三层循环也不必然是 O(n3)O(n^3)O(n​3​​)；循环边界、提前退出以及内层是否重复执行都影响结果。

3.3 每次减半与每次翻倍

while n > 1:
    n //= 2                # 执行约 log₂n 次，O(log n)

i = 1
while i < n:
    i *= 2                 # 同样是 O(log n)

二分查找每次排除约一半候选区间，所以时间复杂度为 O(logn)O(\log n)O(logn)。但“循环里出现除以 2”还不够，必须确认问题规模确实按这个速度缩小。

04.递归算法怎么计算

先写出递归式，再分析递归树或套用主定理：

算法 递归式 时间复杂度
二分查找 T(n)=T(n/2)+O(1)T(n)=T(n/2)+O(1)T(n)=T(n/2)+O(1) O(logn)O(\log n)O(logn)
归并排序 T(n)=2T(n/2)+O(n)T(n)=2T(n/2)+O(n)T(n)=2T(n/2)+O(n) O(nlogn)O(n\log n)O(nlogn)
未去重的斐波那契递归 T(n)=T(n−1)+T(n−2)+O(1)T(n)=T(n-1)+T(n-2)+O(1)T(n)=T(n−1)+T(n−2)+O(1) 指数级，常近似写为 O(2n)O(2^n)O(2​n​​)
记忆化斐波那契 每个 0∼n0\sim n0∼n 状态只计算一次 O(n)O(n)O(n)

递归除了消耗时间，还消耗栈空间。深度为 hhh 的二叉树遍历通常需要 O(h)O(h)O(h) 栈空间；平衡树中 h=O(logn)h=O(\log n)h=O(logn)，退化成链时 h=O(n)h=O(n)h=O(n)。

05.最好、最坏、平均与均摊

这些概念不能混为一谈：

  • 最好情况：某类最有利输入下的成本，例如顺序查找第一个元素就命中，为 O(1)O(1)O(1)。
  • 最坏情况：所有合法输入中最大的成本，常用于保证系统边界。
  • 平均情况：在明确的输入概率分布下计算期望成本，不等于“最好加最坏除以二”。
  • 均摊复杂度：把一长串操作的总成本平均到单次操作上，即使其中某次很贵。
例子 常见结论 原因
快速排序 平均 O(nlogn)O(n\log n)O(nlogn)，最坏 O(n2)O(n^2)O(n​2​​) 划分极不均衡时递归深度和比较次数增加
哈希表查找 平均 O(1)O(1)O(1)，最坏 O(n)O(n)O(n) 大量键冲突时可能退化为线性查找
动态数组追加 均摊 O(1)O(1)O(1) 偶尔扩容复制为 O(n)O(n)O(n)，但不会每次追加都扩容

“快排是 O(nlogn)O(n\log n)O(nlogn)”通常指平均情况；面试或设计系统时要主动补充最坏情况以及如何避免，例如随机选择 pivot、三数取中或 IntroSort 的堆排序兜底。

06.空间复杂度

空间复杂度通常关注除输入本身外需要的额外空间：

  • 只用固定数量的变量：O(1)O(1)O(1)，例如原地双指针。
  • 创建长度随输入增长的辅助数组：O(n)O(n)O(n)。
  • 使用递归：除了显式创建的对象，还要计算调用栈。
  • 返回与输入同规模的结果时，应说明是否把输出空间计入分析。

原地算法不等于没有任何内存开销。例如原地堆排序的额外空间是 O(1)O(1)O(1)；原地快速排序虽然交换元素，但递归栈平均为 O(logn)O(\log n)O(logn)，最坏可到 O(n)O(n)O(n)。

07.常见排序算法速查

算法 平均时间 最坏时间 额外空间 稳定性
冒泡排序 O(n2)O(n^2)O(n​2​​) O(n2)O(n^2)O(n​2​​) O(1)O(1)O(1) 稳定
插入排序 O(n2)O(n^2)O(n​2​​) O(n2)O(n^2)O(n​2​​) O(1)O(1)O(1) 稳定
选择排序 O(n2)O(n^2)O(n​2​​) O(n2)O(n^2)O(n​2​​) O(1)O(1)O(1) 通常不稳定
快速排序 O(nlogn)O(n\log n)O(nlogn) O(n2)O(n^2)O(n​2​​) 平均 O(logn)O(\log n)O(logn) 通常不稳定
归并排序 O(nlogn)O(n\log n)O(nlogn) O(nlogn)O(n\log n)O(nlogn) O(n)O(n)O(n) 稳定
堆排序 O(nlogn)O(n\log n)O(nlogn) O(nlogn)O(n\log n)O(nlogn) O(1)O(1)O(1) 不稳定

稳定性指相等元素的原始相对顺序是否保持不变，它与时间复杂度是两个独立维度。

08.分析步骤与小结

  1. 明确输入规模和要统计的基本操作。
  2. 看循环边界、递归分支、提前退出与数据规模缩减方式。
  3. 顺序代码取较大项，嵌套代码计算实际总次数，递归代码列递归式。
  4. 区分最好、最坏、平均和均摊，并补充额外空间。
  5. 最后用样例或基准测试验证直觉，但不要用单次运行时间替代复杂度分析。

核心结论：复杂度看的是增长趋势，不是循环层数或表面写法；O(nlogn)O(n\log n)O(nlogn) 也不总是快排的完整答案，还要说明输入条件、最坏情况和空间成本。
