红黑树

算法 2021-03-04 · 23 分钟阅读 · 6846 字

为什么需要红黑树

二叉搜索树（BST）满足「左小右大」，查找、插入、删除的复杂度都取决于树高 hhh。如果按有序序列插入，BST 会退化成链表，h=nh = nh=n，所有操作都变成 O(n)O(n)O(n)。

为了让树高始终保持在 O(logn)O(\log n)O(logn)，出现了各种自平衡二叉搜索树：

结构 平衡标准 查找 插入/删除时的旋转 典型应用
AVL 树 左右子树高度差 ≤ 1（严格平衡） 更快 插入最多 2 次，删除可能 O(logn)O(\log n)O(logn) 次 读多写少的场景
红黑树 最长路径 ≤ 2 × 最短路径（近似平衡） 稍慢 插入最多 2 次，删除最多 3 次 Java TreeMap/HashMap 桶树化、C++ std::map、Linux CFS 调度、epoll
B/B+ 树 多路平衡 — 分裂/合并 数据库、文件系统索引（见 B+tree 一篇）

红黑树用「颜色」这一个比特的信息换来了宽松的平衡条件，旋转次数少、写入性能稳定，所以成为工程上最常用的平衡树。

五条性质

  1. 每个节点要么是红色，要么是黑色；
  2. 根节点是黑色；
  3. 每个叶子节点（NIL 空节点）是黑色；
  4. 红色节点的两个子节点都是黑色（不能有两个连续的红节点）；
  5. 从任一节点到其所有后代叶子节点的路径上，黑色节点数目相同（这个数叫黑高 bh）。

为什么能保证 O(logn)O(\log n)O(logn)？ 由性质 5，一棵黑高为 bhbhbh 的子树至少有 2bh−12^{bh}-12​bh​​−1 个内部节点；由性质 4，任意路径上红节点不超过一半，所以 bh≥h/2bh \ge h/2bh≥h/2。于是 n≥2h/2−1n \ge 2^{h/2}-1n≥2​h/2​​−1，即 h≤2log2(n+1)h \le 2\log_2(n+1)h≤2log​2​​(n+1)。

直观理解：把红节点「上提」合并进它的黑色父节点，红黑树就等价于一棵 2-3-4 树（4 阶 B 树）。黑高相同对应 B 树「所有叶子在同一层」，红节点就是 B 树节点里多出来的键。插入时的「变色」对应 4-节点分裂，「旋转」只是调整形状。

基本操作：旋转

旋转是所有平衡树的基础操作，它在 O(1)O(1)O(1) 时间内改变局部结构，同时保持 BST 的中序有序性。

      x                         y
     / \     左旋 left(x)      / \
    a   y    ───────────►     x   c
       / \   ◄───────────    / \
      b   c   右旋 right(y)  a   b

左旋 x：x 的右孩子 y 上位，y 原来的左子树 b 挂到 x 的右边。右旋是镜像操作。

插入

新节点一律染成红色插入（染黑会破坏性质 5，染红最多只破坏性质 4，更容易修）。若父节点是黑色，直接结束；若父节点是红色，出现「红红冲突」，按叔叔节点的颜色分情况修复（以父节点是祖父的左孩子为例，右侧镜像）：

情况 条件 处理
Case 1 叔叔是红色 父、叔染黑，祖父染红，把祖父当作新的当前节点继续向上检查（对应 2-3-4 树的节点分裂）
Case 2 叔叔是黑色，当前节点是父节点的右孩子（之字形） 对父节点左旋，转化成 Case 3
Case 3 叔叔是黑色，当前节点是父节点的左孩子（一字形） 父染黑、祖父染红，对祖父右旋，结束

最后把根染黑。Case 1 可能一路向上传播 O(logn)O(\log n)O(logn) 次，但只变色不旋转；真正的旋转最多 2 次。

Python 实现（插入 + 校验）

用一个共享的黑色哨兵 NIL 代替 None，可以省掉大量判空：

RED, BLACK = True, False


class Node:
    def __init__(self, key, color=RED, nil=None):
        self.key = key
        self.color = color
        self.left = self.right = self.parent = nil


class RBTree:
    def __init__(self):
        self.NIL = Node(None, BLACK)
        self.root = self.NIL

    # ---------- 旋转 ----------
    def _left_rotate(self, x):
        y = x.right
        x.right = y.left
        if y.left is not self.NIL:
            y.left.parent = x
        y.parent = x.parent
        if x.parent is self.NIL:
            self.root = y
        elif x is x.parent.left:
            x.parent.left = y
        else:
            x.parent.right = y
        y.left = x
        x.parent = y

    def _right_rotate(self, x):
        y = x.left
        x.left = y.right
        if y.right is not self.NIL:
            y.right.parent = x
        y.parent = x.parent
        if x.parent is self.NIL:
            self.root = y
        elif x is x.parent.right:
            x.parent.right = y
        else:
            x.parent.left = y
        y.right = x
        x.parent = y

    # ---------- 查找 ----------
    def search(self, key):
        x = self.root
        while x is not self.NIL and x.key != key:
            x = x.left if key < x.key else x.right
        return x is not self.NIL

    # ---------- 插入 ----------
    def insert(self, key):
        z = Node(key, RED, self.NIL)
        parent, cur = self.NIL, self.root
        while cur is not self.NIL:          # 普通 BST 插入
            parent = cur
            cur = cur.left if key < cur.key else cur.right
        z.parent = parent
        if parent is self.NIL:
            self.root = z
        elif key < parent.key:
            parent.left = z
        else:
            parent.right = z
        self._insert_fixup(z)

    def _insert_fixup(self, z):
        while z.parent.color == RED:        # 红红冲突
            g = z.parent.parent             # 父节点是红色，祖父一定存在
            if z.parent is g.left:
                uncle = g.right
                if uncle.color == RED:      # Case 1：叔叔红，变色上移
                    z.parent.color = uncle.color = BLACK
                    g.color = RED
                    z = g
                else:
                    if z is z.parent.right: # Case 2：之字形，先转成一字形
                        z = z.parent
                        self._left_rotate(z)
                    z.parent.color = BLACK  # Case 3：一字形，变色 + 旋转
                    g.color = RED
                    self._right_rotate(g)
            else:                           # 镜像
                uncle = g.left
                if uncle.color == RED:
                    z.parent.color = uncle.color = BLACK
                    g.color = RED
                    z = g
                else:
                    if z is z.parent.left:
                        z = z.parent
                        self._right_rotate(z)
                    z.parent.color = BLACK
                    g.color = RED
                    self._left_rotate(g)
        self.root.color = BLACK

    # ---------- 校验五条性质，返回黑高 ----------
    def check(self):
        def dfs(node, lo, hi):
            if node is self.NIL:
                return 1
            assert (lo is None or node.key >= lo) and (hi is None or node.key <= hi)
            if node.color == RED:
                assert node.left.color == BLACK and node.right.color == BLACK
            lh = dfs(node.left, lo, node.key)
            rh = dfs(node.right, node.key, hi)
            assert lh == rh, "黑高不一致"
            return lh + (node.color == BLACK)

        assert self.root.color == BLACK
        return dfs(self.root, None, None)


if __name__ == '__main__':
    import random
    t = RBTree()
    for k in range(1, 10001):           # 顺序插入，普通 BST 会退化成链表
        t.insert(k)
    print(t.check())                    # 黑高约 12~13，树高不超过 2*log2(n+1) ≈ 27
    t2 = RBTree()
    for k in random.sample(range(100000), 5000):
        t2.insert(k)
    t2.check()
    print(t2.search(42), t.search(5000))

删除（思路）

删除比插入复杂，代码较长，这里只梳理思路：

  1. 先按 BST 规则删除：若被删节点有两个孩子，用它的后继（右子树最小值）替换它，问题转化为删除一个至多有一个孩子的节点；
  2. 如果真正被摘掉的节点是红色，所有性质都不受影响，结束；
  3. 如果被摘掉的是黑色，它所在路径的黑高少了 1。让顶替它的孩子 x 携带一层「额外的黑」：x 若是红色，直接染黑即可；否则按兄弟节点 w 分四种情况修复：
    • Case 1：w 红 → w 染黑、父染红、对父旋转，转成 w 为黑的情况；
    • Case 2：w 黑且 w 的两个孩子都黑 → w 染红，额外的黑上移到父节点继续处理；
    • Case 3：w 黑，w 的近侧孩子红、远侧孩子黑 → 对 w 旋转并变色，转成 Case 4；
    • Case 4：w 黑，w 的远侧孩子红 → w 取父色、父染黑、远侧孩子染黑，对父旋转，结束。

删除最多旋转 3 次，变色可能向上传播 O(logn)O(\log n)O(logn) 次。

复杂度

操作 时间 说明
查找 O(logn)O(\log n)O(logn) 树高 ≤2log2(n+1)\le 2\log_2(n+1)≤2log​2​​(n+1)
插入 O(logn)O(\log n)O(logn) 旋转 ≤ 2 次
删除 O(logn)O(\log n)O(logn) 旋转 ≤ 3 次
空间 O(n)O(n)O(n) 每节点额外 1 bit 颜色 + parent 指针

常见面试问题

  • 红黑树和 AVL 树怎么选？ AVL 更严格平衡，查找略快但写入时旋转更多；红黑树写入代价稳定，适合增删频繁的场景，所以语言标准库普遍选红黑树。
  • 为什么 Java 8 HashMap 链表长度 ≥ 8 时转红黑树？ 哈希冲突严重时链表查找退化为 O(n)O(n)O(n)，转红黑树后为 O(logn)O(\log n)O(logn)；阈值 8 是按泊松分布估算的，正常情况下几乎不会触发；数组容量小于 64 时优先扩容而不是树化；节点数减少到 6 时退回链表，中间留出余量避免反复转换。
  • 为什么数据库索引不用红黑树？ 红黑树是二叉的，数据量大时树高仍有二三十层，每层一次磁盘 IO 太慢；B+ 树多路、矮胖，且叶子节点链表化便于范围查询。
  • 新插入节点为什么是红色？ 插黑色必然破坏所有路径黑高相同（性质 5），插红色只有父节点也为红时才需要修复。

小结

  • 红黑树 = BST + 颜色约束，用「近似平衡」换取更少的旋转，保证 h≤2log2(n+1)h \le 2\log_2(n+1)h≤2log​2​​(n+1)；
  • 插入看叔叔：叔红变色上移，叔黑旋转（之字形先转一字形）；
  • 删除看兄弟：四种情况，核心是消除「额外的黑」；
  • 理解它和 2-3-4 树的对应关系，比死记情况表更容易写对。
