Zabbix基础

操作系统 2021-02-09 · 16 分钟阅读 · 4536 字

01.Zabbix 是什么

Zabbix 是一款开源的企业级分布式监控系统，可以监控服务器、网络设备、虚拟化、数据库、中间件和应用等，提供数据采集、告警、可视化、自动发现等完整能力，全部功能通过 Web 界面配置。

为什么需要监控：

  • 事前预警：磁盘快满、负载过高时提前告警，而不是等服务挂了才发现。
  • 事后排查：保留历史数据，便于分析故障发生时的资源变化。
  • 容量规划：根据趋势数据评估扩容时机。

版本说明：Zabbix 的 LTS 版本有 5.0、6.0、7.0（每个 LTS 提供 5 年支持），新部署建议直接使用 7.0 LTS 或 6.0 LTS。6.0 起服务端要求 PHP 7.4+，并原生支持高可用集群（HA）；7.0 增加了 Proxy 负载均衡、更多仪表盘组件等。

02.架构与组件

flowchart LR
    A1[Agent / Agent 2
被监控主机] -->|10050/10051| S[Zabbix Server]
    A2[SNMP / IPMI / JMX
网络设备、Java 应用] --> S
    A3[被监控主机] --> P[Zabbix Proxy] -->|10051| S
    S --> DB[(MySQL / PostgreSQL)]
    W[Web 前端
Nginx/Apache + PHP] --> DB
    W --> S
组件 作用
Zabbix Server 核心，负责接收数据、计算触发器、发送告警，默认监听 10051
数据库 保存配置和历史数据，支持 MySQL/MariaDB、PostgreSQL（可配合 TimescaleDB）
Web 前端 PHP 编写的管理界面
Zabbix Agent 安装在被监控主机上采集数据，默认监听 10050
Zabbix Agent 2 Go 编写的新一代 Agent，支持插件，内置 MySQL、Redis、Docker 等监控
Zabbix Proxy 代理，替 Server 采集数据后再转发，用于跨机房、分担 Server 压力

03.核心概念

理解 Zabbix 的关键是搞清楚以下对象之间的关系：

flowchart LR
    H[主机 Host] --> I[监控项 Item]
    I --> T[触发器 Trigger]
    T --> E[事件 Event]
    E --> AC[动作 Action]
    AC --> M[告警媒介 Media]
    TPL[模板 Template] -.包含.-> I
    TPL -.包含.-> T
概念 说明
主机（Host） 被监控的对象，如一台服务器、一台交换机
主机群组（Host group） 主机的逻辑分组，便于权限和批量管理
监控项（Item） 要采集的一个具体指标，例如 system.cpu.load[all,avg1]
触发器（Trigger） 基于监控项数据的判断表达式，定义什么情况算"有问题"
事件（Event） 触发器状态变化产生的记录
动作（Action） 事件发生后要做什么：发消息、执行远程命令
告警媒介（Media type） 邮件、钉钉/企业微信/飞书 Webhook、短信等
模板（Template） 监控项、触发器、图形、自动发现规则的集合，可批量关联到主机
自动发现（LLD） 低级别发现，自动发现磁盘分区、网卡、端口等并生成监控项

3.1 主动模式与被动模式

模式 方向 说明
被动（passive） Server → Agent:10050 Server 主动来要数据，Agent 配置 Server=
主动（active） Agent → Server:10051 Agent 从 Server 拉取监控项列表后主动上报，配置 ServerActive=

主机较多时推荐主动模式，可以显著减轻 Server 的轮询压力，也更适合 Agent 在 NAT 后面的场景。

3.2 触发器表达式

Zabbix 5.4 起触发器使用新语法 函数(/主机/监控项键值, 参数)：

# 最近 5 分钟 CPU 1 分钟平均负载都大于 5
min(/Linux server/system.cpu.load[all,avg1],5m)>5

# 根分区可用空间低于 10%
last(/Linux server/vfs.fs.size[/,pfree])<10

# 3 分钟内没有收到 Agent 数据
nodata(/Linux server/agent.ping,3m)=1

触发器严重级别：未分类、信息、警告、一般严重、严重、灾难。

04.安装部署（以 Rocky/RHEL 9 + Zabbix 7.0 + MySQL 为例）

具体仓库地址以 Zabbix 官网下载页面生成的命令为准，大致流程如下：

# 1. 安装 Zabbix 官方仓库
#    在官网下载页选择 版本/系统/数据库/Web 服务器 后，复制页面给出的 zabbix-release 包地址
rpm -Uvh <官网下载页给出的 zabbix-release rpm 地址>
dnf clean all

# 2. 安装 Server、前端、Agent
dnf install -y zabbix-server-mysql zabbix-web-mysql zabbix-nginx-conf \
    zabbix-sql-scripts zabbix-selinux-policy zabbix-agent2

# 3. 创建数据库（MySQL 中执行）
#   create database zabbix character set utf8mb4 collate utf8mb4_bin;
#   create user zabbix@localhost identified by 'password';
#   grant all privileges on zabbix.* to zabbix@localhost;
#   set global log_bin_trust_function_creators = 1;

# 4. 导入初始表结构和数据
zcat /usr/share/zabbix-sql-scripts/mysql/server.sql.gz | \
    mysql --default-character-set=utf8mb4 -uzabbix -p zabbix
#   导入完成后：set global log_bin_trust_function_creators = 0;

# 5. 配置数据库密码
vim /etc/zabbix/zabbix_server.conf      # DBPassword=password

# 6. 启动服务
systemctl enable --now zabbix-server zabbix-agent2 nginx php-fpm

然后浏览器访问 Web 前端完成初始化向导，默认账号 Admin / zabbix（注意 A 大写），登录后第一时间修改密码。

05.Agent 配置

被监控主机安装 Agent 2，修改 /etc/zabbix/zabbix_agent2.conf：

Server=192.168.1.10            # 允许被动模式连接的 Server/Proxy 地址
ServerActive=192.168.1.10      # 主动模式上报地址
Hostname=web01                 # 必须与 Web 中配置的主机名称完全一致

systemctl enable --now zabbix-agent2
firewall-cmd --permanent --add-port=10050/tcp && firewall-cmd --reload

在 Server 端用 zabbix_get 测试被动模式取数（需安装 zabbix-get 包）：

zabbix_get -s 192.168.1.21 -k system.uname
zabbix_get -s 192.168.1.21 -k "vfs.fs.size[/,pfree]"

之后在 Web 中：数据采集 → 主机 → 创建主机，填写主机名称、群组、Agent 接口 IP，关联模板 Linux by Zabbix agent（主动模式可选 Linux by Zabbix agent active）即可。

06.自定义监控项

当内置键值不满足需求时，可以用 UserParameter 自定义：

# /etc/zabbix/zabbix_agent2.d/custom.conf
UserParameter=nginx.active,curl -s http://127.0.0.1/nginx_status | awk '/Active/{print $3}'
UserParameter=tcp.state[*],ss -ant | awk 'NR>1 && $$1=="$1"' | wc -l
  • 带 [*] 的键值可以接收参数，脚本中用 $1、$2 引用；awk 中自身的 $1 要写成 $$1 进行转义。
  • 修改后重启 Agent，并先用 zabbix_get -k nginx.active 验证能取到数据，再到 Web 中添加监控项。

07.告警配置流程

  1. 告警 → 媒介：启用并配置邮件或 Webhook（钉钉、企业微信、飞书等）。
  2. 用户 → 报警媒介：给接收告警的用户添加媒介和收件地址。
  3. 告警 → 动作 → 触发器动作：设置条件（如严重级别 ≥ 一般严重），在"操作"中选择发送给哪些用户/用户组，并可配置恢复通知。

08.常见问题

  1. 主机可用性图标变红：Server 无法连接 Agent 10050 端口，检查防火墙、Agent 的 Server= 是否包含 Server IP。
  2. 主动模式无数据：Agent 中的 Hostname 与 Web 中主机名称不一致；或 Server 的 10051 端口未放行。
  3. Web 中文乱码：图形中中文显示为方块，需要把中文字体替换到前端字体目录（如 /usr/share/zabbix/assets/fonts/，路径随版本有差异）。
  4. 数据库膨胀：历史数据量大，需要合理设置监控项的历史/趋势保留时间，大规模场景使用 PostgreSQL + TimescaleDB 分区。
  5. “Zabbix server is not running”：前端连不上 Server，检查 zabbix-server 进程、日志 /var/log/zabbix/zabbix_server.log 和 SELinux。

小结

  • Zabbix = Server + 数据库 + Web + Agent（可选 Proxy），端口 10050（Agent）/ 10051（Server）。
  • 核心链路：主机 → 监控项 → 触发器 → 事件 → 动作 → 媒介，用模板批量管理。
  • 主机多时优先用主动模式；不满足需求时用 UserParameter 自定义监控项。
  • 新部署选择 7.0 / 6.0 LTS，并在初始化后立即修改默认 Admin 密码。
